# StaffGo landing

Лендинг StaffGo. Production-домен: https://staffgo.by.

## Что изменено

- Первый экран стал продуктовым: два понятных CTA и mockup реального сценария работы.
- Убран шаблонный SaaS-подход с повторяющимися одинаковыми карточками.
- Добавлены отдельные сценарии: временные смены, найм в штат, работа с проектными исполнителями и заказчиками.
- Отдельно раскрыт сценарий для блогеров, авторов, фотографов, дизайнеров и специалистов на проектах.
- Блок документов переведен с юридического языка на понятный пользовательский сценарий.
- Переработан блок «Обычно / StaffGo» с живой подачей.
- Сферы расширены до мероприятий, контента и digital.
- Вакансии оформлены как продуктовый список, а не маркетинговые карточки.
- Сохранены реальные показатели текущего сайта: 7000+ исполнителей, вся Беларусь, 24 часа, цифровой документооборот.
- Сохранены реальные юридические данные и ссылки на опубликованные документы.
- Все CTA ведут на существующий личный кабинет или рабочие разделы страницы.
- Добавлены keyboard/focus states, `prefers-reduced-motion`, semantic HTML, canonical, OpenGraph, Organization schema, robots.txt и sitemap.xml.

## Файлы

- `index.html` — страница.
- `styles.css` — адаптивная дизайн-система и layout.
- `script.js` — меню, tabs и reveal-анимации.
- `assets/staffgo-logo.png` — предоставленный пользователем логотип высокого разрешения (2172 × 724, PNG с прозрачностью).
- `assets/staffgo-icon.png` — иконка StaffGo из предоставленного бренд-борда.
- `robots.txt`, `sitemap.xml` — базовые SEO-файлы.

## Запуск

Откройте `index.html` напрямую или запустите любой статический сервер, например:

```bash
python3 -m http.server 8080
```

Затем откройте `http://localhost:8080`.

## Важно перед production

Логотип заменён на предоставленный PNG высокого разрешения без перекодирования. Все четыре размещения используют один файл; пропорции сохранены.

## SEO и переезд

Canonical, og:url, Organization JSON-LD, robots.txt и sitemap.xml используют https://staffgo.by.
Sitemap статический: генератора и env/config в этом проекте нет. Сейчас индексируется только главная страница. При добавлении страниц добавляйте их канонические URL на https://staffgo.by в sitemap.xml.
Ссылки на кабинет используют уже указанный в проекте https://platform.alcan.by/; новый домен кабинета не задан.

### Серверные 301-редиректы

`deploy/nginx-legacy.conf` подключается в контексте `http` Nginx на сервере старого домена. Он обрабатывает HTTP и HTTPS, основной домен и www; сохраняет исходный path и query через `$request_uri`. Конфигурация не относится к поддомену кабинета.

Перед включением:
1. Направьте DNS старого домена и www на сервер редиректов.
2. Укажите действительные пути к сертификату и ключу, покрывающим оба имени. Сохраняйте автоматическое обновление сертификата (например, через DNS challenge).
3. Подключите конфигурацию вместо прежних server-блоков этих имен, выполните `nginx -t` и перезагрузите Nginx.
4. Опубликуйте обновленные index.html, robots.txt и sitemap.xml на новом домене. Не публикуйте deploy/ и README.md как файлы сайта.
5. Проверьте 301 и заголовок Location для главной, вложенного пути и пути с query по HTTP и HTTPS. Проверьте доступность соответствующих страниц на новом домене: этот репозиторий содержит только главную, остальные маршруты обслуживает основной сайт.

Само копирование статических файлов не включает серверные редиректы. Доступа к production-серверу в этом проекте нет.

Документация Nginx: https://nginx.org/en/docs/http/ngx_http_rewrite_module.html#return и https://nginx.org/en/docs/http/ngx_http_core_module.html#var_request_uri


## Скорость загрузки

Страница использует оптимизированный логотип `assets/staffgo-logo-456.webp` (456 × 152, подходит до 3x при ширине 152 px). Оригинал PNG сохранён. При замене логотипа обновляйте обе версии.
Текст виден сразу, без зависимости от JavaScript и IntersectionObserver. Скрипт загружается с defer, внешние шрифты и библиотеки не используются.
`deploy/nginx-performance.conf` подключается внутри server-блока нового домена: gzip для текстовых ресурсов, кеширование статики на 7 дней и перепроверка HTML. Согласуйте location-блоки с существующим конфигом и выполните nginx -t перед перезагрузкой. При обновлении CSS/JS меняйте параметр версии в index.html.
После публикации проверьте PageSpeed Insights на реальном домене: локальная оценка не измеряет production-сервер и сеть.
